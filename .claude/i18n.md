# i18n Architecture

## Overview

Two locales: **`en`** (default/fallback) and **`es`**.  
Stack: `i18next` + `react-i18next` + `i18next-resources-to-backend`.  
All public routes are locale-prefixed: `/{lang}/...`

---

## Key Files

| File | Role |
|---|---|
| `src/i18n/settings.ts` | Single source of truth: `languages`, `fallbackLng`, `defaultNS` |
| `src/i18n/index.ts` | `getTranslation(lang)` — server-side i18next init |
| `src/i18n/client.ts` | `i18next` client-side init |
| `src/i18n/I18nContext.tsx` | `<I18nProvider>` — wraps the client component tree |
| `src/i18n/useTranslations.ts` | `useTranslations()` hook for Client Components |
| `src/i18n/useLocale.ts` | `useLocale()` — returns current locale string in Client Components |
| `src/i18n/locales/en/translation.json` | English strings |
| `src/i18n/locales/es/translation.json` | Spanish strings |

---

## Locale Detection (Middleware)

`src/middleware.ts` runs on every request (except `/api`, `/_next`, `/studio`, `/sitemap.xml`, `/robots.txt`).

1. If the path has no locale prefix → redirect to `/{fallbackLng}{pathname}`.
2. If the path has a valid locale prefix → set `x-locale` response header.

The root layout (`src/app/layout.tsx`) reads `x-locale` from headers to set `<html lang="...">`.

## Server Components

Import `getTranslation` from `@/i18n`:

```ts
import { getTranslation } from "@/i18n"

export default async function MyPage({ params }: { params: Promise<{ lang: string }> }) {
  const { lang } = await params
  const { t } = await getTranslation(lang)

  return <h1>{t("hero.title")}</h1>
}
```

---

## Client Components

The `<I18nProvider>` is rendered in `src/app/(root)/[lang]/layout.tsx` — it pre-loads translations server-side and passes them to the client tree, avoiding a round-trip.

In Client Components:

```ts
"use client"
import { useTranslations } from "@/i18n/useTranslations"

export function MyButton() {
  const { t } = useTranslations()
  return <button>{t("common.submit")}</button>
}
```

To read the current locale:

```ts
"use client"
import { useLocale } from "@/i18n/useLocale"

export function LangBadge() {
  const lang = useLocale()
  return <span>{lang.toUpperCase()}</span>
}
```

## Sanity Localised Fields

Sanity fields that vary by language are stored as plain objects (not using the Sanity i18n plugin):

```json
{ "en": "Hello", "es": "Hola" }
```

Access in a Server Component page:

```ts
const { lang } = await params
const data = await client.fetch(...)

// data.title is { en: "...", es: "..." }
return <h1>{data.title[lang]}</h1>
```

## Adding a New Translation Key

1. Add the key to `src/i18n/locales/en/translation.json`.
2. Add the translated value to `src/i18n/locales/es/translation.json`.
3. Use `t("your.key")` in the component.

Both files must be updated together — missing keys fall back to `en` silently.

---

## Adding a New Locale

1. Add the locale code to `languages` in `src/i18n/settings.ts`.
2. Create `src/i18n/locales/<code>/translation.json` with all keys translated.
3. Update `src/app/(root)/[lang]/layout.tsx` to import the new translation file.
4. Update `src/app/sitemap.ts` to include the new locale in all routes.
5. Verify `hreflang` alternates in `generateMetadata()` across all pages.
